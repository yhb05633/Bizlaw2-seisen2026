# Bizlaw2-seisen2026 v4 設計スペック(解答ボタン・メモ・マスター機能)

## 背景

v1〜v3で構築したフラッシュカードアプリに、以下の機能追加を行う:

1. 選択肢を選んでから押す「解答ボタン」(回答カードへ移動)
2. 「できた」「苦手」ボタンの廃止
3. 回答カードに「マスター」ボタン(トグル)を追加
4. 目次ページに章ごとのマスター数・比率を表示
5. 目次ページに「マスタースキップ」トグルを追加(マスター済みの問題を出題から除外)
6. 回答カードに自由記述のメモ欄(音声入力対応、textareaであれば標準対応)を追加し、目次ページの「メモ一覧」ボタンから一覧・ジャンプできるようにする

前提として、2章第10問(選択肢後の「※」注記)・12章第15問(選択肢が甲/乙の2行にまたがる)は、既に選択肢抽出ロジックを拡張し、他の問題と同じ選択式に修正済み。これにより現時点で選択肢を持たない(地の文表示・選択不可)問題は、下線部が直接選択肢になっている1章第6問・9章第13問の2問のみで、この2問も下線部が選択可能なため、実質的に全172問が「選択可能な要素を持つ」状態になっている。

## 機能ごとの設計

### ① 解答ボタン

- 問題(表)カードに「解答を見る」ボタンを追加。
- 選択可能な要素(選択肢または下線部)が1つ以上存在するカードでは、いずれかを選択するまでボタンをグレーアウト(無効化)する。選択可能な要素が万一存在しないカードでは最初から有効にする(将来のデータ変化に対する保険)。
- ボタンを押すと回答カードに移動する(既存の「カードタップで反転」と同じ処理を呼び出す)。
- 既存の「カードをタップすると反転する」操作はそのまま残し、こちらは選択状態にかかわらず常に反転できる(グレーアウトの制約を受けるのは解答ボタンのみ)。

### ② できた/苦手ボタンの削除

- 表裏カードから`.progress-buttons`(できた/苦手ボタン)を削除。
- 関連するJS(`getProgress`/`setProgress`/`updateProgressButtons`とその呼び出し)、CSS、`localStorage`キー(`bizlaw2seisen:progress:*`)へのアクセスをすべて削除する。既存に保存された値は触れない(単に読み書きしなくなるだけ)。

### ③ マスターボタン

- 回答(裏)カードに「マスター」ボタンを設置。押すとそのカードを「マスター済み」として`localStorage`に記録し、ボタンが強調表示(色付き)になる。もう一度押すと解除する(トグル)。
- キー形式: `bizlaw2seisen:master:{cardId}`(値がある=マスター済み、削除=未マスター)。

### ④ 目次ページのマスター表示

- 各章ボタンに2行目として「マスター {mastered}/{total}（{pct}%）」を表示する。「すべて」ボタンにも同様に全172問に対する合計を表示する。
- 表示は章一覧を描画する際に毎回`localStorage`から算出する(専用の集計データは持たない)。

### ⑤ マスタースキップ

- 目次ページに1つのトグルボタン(例:「マスタースキップ: OFF」⇔「マスタースキップ: ON」)を設置。状態は`localStorage`に保存し、目次ページを開くたびに復元する。
- ONの状態で章(または「すべて」)を開始すると、その章(または全体)のカードのうちマスター済みのものを出題対象から除外する。
- 除外した結果、出題対象が0件になった場合は「この章はすべてマスター済みです」等のメッセージを表示し、カード画面には遷移しない。

### ⑥ メモ機能

- 回答(裏)カードのみに自由記述の`<textarea>`を設置。入力するたびに`localStorage`に保存する(キー形式: `bizlaw2seisen:memo:{cardId}`、空にすると削除)。
- `<textarea>`は標準のテキスト入力要素なので、Mac/iPhoneの音声入力(Typeless・標準ディクテーション問わず)がそのまま使える。iOS Safariの自動ズームを防ぐため`font-size`は16px以上にする。
- textarea内のクリック/タップはカードの反転(`#card`のクリックイベント)を発火させないようにする(`stopPropagation`)。
- 目次ページに「メモ一覧」ボタンを追加。押すとオーバーレイが開き、メモが入力されている全カードを「第N章 第M問（タイトル）」+メモ本文の形で一覧表示する(メモが1件もない場合はその旨を表示)。
- 一覧の各項目をタップすると、オーバーレイを閉じてその問題のカード画面(回答面)に直接遷移する。この遷移はマスタースキップ設定を無視する(スキップ対象でも必ず開ける)。

## データモデルの変更

`cards.js`のカードスキーマは変更しない(v3までと同じ)。今回の追加要素(マスター状態・メモ本文・マスタースキップ設定)は、すべて`localStorage`側の状態として扱い、`cards.js`側のデータには含めない。

## スコープ外

- メモ・マスター状態の端末間同期、サーバー保存
- メモの検索・編集履歴
- マスタースキップの章ごとの個別設定(グローバル1つのみ)
