# Bizlaw2-seisen2026 設計スペック

## 目的

ビジネス実務法務検定2級の精選問題集(`/Volumes/Macmini M2PRO/専門スキル/法務書籍/Legalstudy2026/ビジ法検定_/ビジ法２精選/01.txt`〜`16.txt`、全16章・計172問)を使った、Mac/iPhone向けフラッシュカードWebアプリ。

既存の類似プロジェクト(`ビジ法2級`、`ビジ法2級_32問選択肢○×`、`ビジ法3級模擬試験`)と同じ「単一HTML静的Webアプリ+GitHub Pages+ホーム画面追加でPWA化」という方式を踏襲する。

## データソースの課題

元データは16個のテキストファイルで、章ごとに表記が不揃い:

- 見出しレベルが `#`〜`####` とバラバラ
- 「設問」「問題」の表記ゆれ
- 12.txt は見出し(`#`)を一切使わないプレーンテキスト
- 09.txt・10.txt・12.txt は章タイトルの見出しが無い、または不正確

これを解決するため、章メタデータ(章番号・章タイトル・問題数)をユーザー提供の目次情報から正としてスクリプト内にハードコードし、パース結果の問題数を突き合わせて検証する。

## ① データパイプライン

`scripts/parse_cards.py`(Python標準ライブラリのみ、外部依存なし)。

- 各 `NN.txt` を読み込み、正規表現で「第N問」を区切りとして問題ブロックに分割する。見出しレベル(`#`〜`####`の有無)や「設問」「問題」表記の違いを許容する柔軟なパターンを使う。
- 各ブロックから以下を抽出し、共通スキーマのレコードにする:
  ```
  { id, chapter, chapterTitle, examRef, question, answer, explanation }
  ```
  - `question` / `explanation` は元の**太字**や箇条書きを保った軽量マークダウン文字列(選択肢ア〜オ・①〜⑤は本文に含めたテキストとして保持し、構造化はしない)。
  - `examRef` は「第45回 第3問 3-3」のような出典表記(無い場合は空文字)。
  - `chapter` / `chapterTitle` は上表のハードコードされたメタデータから採番する(ファイル内の見出しには依存しない)。
- ファイルごとにパース後の問題数を上表の問題数と突き合わせ、一致しなければエラーとしてコンソールに出力し、該当ファイルと差分件数を明示する。
- パースに失敗した(想定パターンに当てはまらない)ブロックも同様にコンソールへ一覧出力する。
- 出力は `cards.js`(`const CARDS = [...]` 形式、章メタデータ配列 `const CHAPTERS = [...]` も含む)。
- 元の `.txt` ファイルには一切変更を加えない。txt側を修正した場合はスクリプトを再実行するだけで `cards.js` に反映できる。

## ② アプリ本体

`index.html` 1ファイル完結の静的Webアプリ(HTML/CSS/JS、外部ライブラリ依存なし)+ 生成された `cards.js` を読み込む構成。

- **章選択画面**: 上表の章番号・章タイトル・問題数を一覧表示し、タップで学習開始(章単独 or 「すべて」)。
- **カード画面**: 章内カード表示。フリップ式(表:問題文、裏:正解+解説)。
- 画面上部のスライダで問題番号にジャンプ可能(既存アプリと同様)。
- 各カードに「できた/苦手」ボタンを設置し、状態は端末の `localStorage` に保存(カードIDごと)。他端末・ブラウザ間では同期しない。
- 簡易マークダウン(太字・改行・箇条書き)をHTMLに変換する軽量関数を自前で実装(外部ライブラリ不使用の既存方針を踏襲)。
- PWA化: `manifest.json` + `sw.js`(オフラインキャッシュ)+ アイコン一式(既存アプリのアイコンを流用/踏襲)。

## ③ 進め方

1. `プロジェクト/フラッシュカードアプリ/Bizlaw2-seisen2026/` フォルダに一式を作成。
2. Macのブラウザで `index.html` を直接開いて動作確認・調整(章選択・フリップ・進捗保存・スライダ)。
3. 問題なければ GitHub リポジトリ `Bizlaw2-seisen2026` を新規作成しpush → GitHub Pages で公開(`https://yhb05633.github.io/Bizlaw2-seisen2026/`)。
4. iPhoneのSafariで開き「ホーム画面に追加」。ビルドし直しは不要、Macで確認したものがそのままiPhone版として動作する。

## テスト方針

- `parse_cards.py` は各章の問題数が期待値と一致することを検証(上表ベース)。件数不一致・パース失敗は明示的にエラー出力する。
- アプリ側は自動テストを設けず、ブラウザでの手動確認(章選択・カード表示・フリップ・進捗保存・スライダジャンプ・PWAインストール)で検証する。

## スコープ外

- サーバー同期・複数端末間の進捗共有
- 苦手問題のみの絞り込み表示
- 選択肢(ア〜オ、①〜⑤)の構造化・自動採点
